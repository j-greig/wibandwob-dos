Animated primers (multi-frame with --- separators) play at a fixed frame rate.
They should be able to sync to BPM.

Concept:
- A 4-frame animation at 128 BPM in 4/4 = one frame per beat = ~469ms per frame
- An 8-frame animation synced to hi-hats = one frame per eighth note = ~234ms
- A 2-frame animation synced to half-notes = ~938ms

The timeline format could specify animation speed per window:
  { "role": "kick-viz", "open": { "type": "primer", "file": "kick-anim.txt" },
    "layout": "sidebar-left", "frameSync": "beat" }

frameSync options: "beat", "half", "eighth", "bar", or explicit ms value.

This requires either:
- A control API endpoint to set primer animation speed per window
- Or generating the primer with the right number of duplicate frames to match BPM

The duplicate-frames approach works without app changes:
  128 BPM = 469ms/beat. If primer animates at ~200ms/frame,
  duplicate each frame 2x to get ~400ms effective rate.
  
Agent can generate these programmatically when writing timelines.
