Some windows/commands crash or silently fail in Docker/VPS environments (missing native deps, no camera, no API key, no mediapipe venv). Rather than shipping a broken command palette, introduce a mechanism to mark commands as disabled per deployment profile.

## Options

A) `WIBWOB_DISABLED_COMMANDS=monster_cam.open,backrooms.run` env var — comma-separated list filtered out of /commands/list and menus
B) Module-level `capabilities` export — each module declares what it needs (camera, anthropic-key, figlet, etc.) and a capability resolver disables modules whose deps are absent at startup
C) `config/docker-profile.ts` — a static list of enabled command ids for the Docker profile, imported by command-catalog.ts

Prefer B long term (self-describing modules), but C is fastest to ship.

## Currently broken in Docker (comment out for now)
- monster_cam.open — needs Python + mediapipe venv + camera
- backrooms.run / backrooms.open — needs claude CLI + ANTHROPIC_API_KEY
- microapp.wibwob.poetry-clock sentient/liminal/terrain modes — needs ANTHROPIC_API_KEY
- chrome.open — headless browser extraction may fail without chromium deps
- art.open — depends on what the art engine needs (TBC)

## Safe list (confirmed working in smoke)
- WibWobWorld, ISO viewer, World Chatroom
- Plasma, Contour, Terrain Lab, Triptych, Pattern, FIGlet, Primer viewer/gallery
- TR-808, Poetry Clock (clock mode only), Music Player
- Text Editor, Document Reader, File Finder
- Wib&Wob Agent (if ANTHROPIC_API_KEY injected)
- Inspector, Palette, Workspace Manager, Scramble
