## Goal
Pi agents should be able to open Scramble's session log the same way they open their own — via the session log path in `~/.pi/agent/sessions/`.

## Current state
- Scramble writes JSONL to `scratch/scramble-sessions/scramble-XXXXXX.jsonl`
- The format is simple `{role, content, timestamp}` — NOT the full pi session format (which has `{type:"message", id, parentId, ...}`)
- The floating window info bar shows the session ID and clicking it opens the log in an editor window

## Options

**Option A (simple):** Leave as-is, just make sure `GET /scramble/state` returns `logPath` (already done). Agents read the log via the API or file read tools.

**Option B (pi-native):** Write Scramble's log in pi session format and symlink into `~/.pi/agent/sessions/<cwd>/`. Then Wib&Wob agent can use `/resume <id>` to load the transcript. Heavier — requires matching the pi session schema.

**Option C (hybrid):** Keep simple JSONL but also write a minimal pi-compat session header so the file can be browsed in the agent log viewer.

## Recommendation
Option A for now — log path is in `/scramble/state`, clicking info bar opens it. Revisit if agents need to resume Scramble conversations.
