## What
A host-side registry that classifies microapps into tiers (core/beta/internal) and controls visibility across all surfaces (menu, palette, API, CLI, agent).

## Why (COAT)
Status is a **host decision**, not a microapp-author decision. Putting it in microapp.json would be adapter-owned semantics. The host operator decides what's promoted.

## Design
- Registry file: `src/core/microapp-registry.ts` (or JSON config)
- Three tiers: `core` (always visible), `beta` (opt-in/power users), `internal` (dev only)
- Loader reads registry at load time, tags each microapp's commands with tier
- Surfaces filter by tier:
  - **Menu**: core always, beta in submenu or flagged, internal hidden
  - **Palette**: core + beta, internal hidden
  - **API** `/commands/list`: includes tier field, optional `?tier=core` filter
  - **CLI** `wibwob commands`: shows tier column
  - **Agent**: core + beta visible to agent tools
- Workspace saves can include `disabledApps: string[]` and/or `disabledTiers: string[]`
- Unregistered microapps default to `beta` (safe default)

## Classification (initial)
- **core**: wibwob.figlet, wibwob.contour, wibwob.command-lab, wibwob.runtime-inspector
- **beta**: wibwob.plasma, wibwob.generative, wibwob.workspace-beacon, wibwob.layout-probe
- **internal**: demo-* microapps, test fixtures
