## Brief (REVISED)

The music video should use WibWob-DOS itself as the visual substrate.
Windows are panels. The desktop is the frame. Primers are actors.
Figlets are titles. The tracker is the music commenting on itself.
The chat window is dialogue. Scramble reacts.

Like a graphic novel that is also a music video that is also a DOS desktop.

Gondry (handmade, stop-motion) × Shrigley (deadpan absurd) × Cunningham (hypnotic precision)

## Format: Timed Workspace JSON

A workspace JSON with timecodes per window:

```json
{
  "bpm": 155,
  "duration": 45,
  "theme": "wibwob-dark",
  "canvas": { "cols": 135, "rows": 120 },
  "windows": [
    {
      "type": "figlet",
      "title": "WIB&WOB",
      "text": "WIB&WOB",
      "enter": 0.8,
      "exit": 8.5,
      "x": 40, "y": 3, "w": 55, "h": 10,
      "focused": true,
      "effects": ["judder_on_beat"]
    },
    {
      "type": "primer",
      "title": "flatboy.txt",
      "primer": "flatboy",
      "enter": 3.0,
      "exit": 8.5,
      "x": 5, "y": 38, "w": 18, "h": 14
    }
  ]
}
```

This is the right abstraction — separates choreography from rendering.
The renderer reads the spec and draws frames. The spec is editable.
Could eventually be played back by the live app too.

## Architecture Reference

The C++ WibWob-DOS had a feature (or concept) for timed workspace playback —
workspace JSON with enter/exit times for figlet windows. This is that idea
generalised to all window types.
