## 2026-03-23 — Ghostty shaders + View menu + /plan prompt

### Ghostty 1.3 changed config filename — script hardcoded old path

**Pain:** `ghostty-shader.sh` assumed `config`, Ghostty 1.3+ uses `config.ghostty`. Silent failure.

**Why:** Hardcoded path, no version discovery.

**Fix:** Cascade fallback — try `config.ghostty` first, then `config`, then XDG. Lesson: version-dependent paths need ordered discovery.

---

### `fswatch` watcher dies immediately when spawned from `bash script.sh`

**Pain:** `disown` doesn't survive non-interactive shell exit — child gets SIGHUP. Inline `bash -c` with complex quoting also fails silently.

**Why:** Non-interactive shells don't have job control; `disown` is a no-op.

**Fix:** Write watcher body to a temp script file, run with `nohup bash $tmpfile &`.

---

### `pgrep -x Ghostty` misses running process

**Pain:** Check returned false even with Ghostty running.

**Why:** macOS app bundle name (`Ghostty`) ≠ binary name (`ghostty`).

**Fix:** `pgrep -xi` (case-insensitive).

---

### Dynamic menu command registered after `buildMenus()` doesn't appear

**Pain:** `addDynamic()` registered `ghostty.shaders` but it wasn't in the View menu.

**Why:** `buildMenus()` snapshots `dynamicCommands` at call time. Register-after-build = invisible.

**Fix:** Register dynamics *before* `rebuildMenusFromCommands()`.

---

### `ghosttyShaderList` split bug — space-separated output parsed as newline

**Pain:** API returned one blob instead of a shader list.

**Why:** `.split("\n")` on space-separated output. Pre-existing bug — script path was also wrong (`scripts/ghostty-shader.sh` doesn't exist).

**Fix:** `.split(/\s+/).filter(Boolean)`. Extracted shader logic to `ghostty-shader-service.ts`.

---

### Reloading TUI code requires full quit + relaunch, not Ctrl+C

**Pain:** Ctrl+C restarts the process with cached bytecode — new code doesn't land.

**Why:** Bun caches compiled TS. Ctrl+C = restart same binary.

**Fix:** Ctrl+Q (app quit) → `bun run dev:world`. Built `restart-wibwob.sh` to automate.

## 2026-03-23 — W12 retro tagging with parallel haiku agents

### Haiku over-tags continuation lines

**Pain:** Blob2/3/4 had haiku tagging mid-sentence continuation lines of multi-line bullets.

**Why:** Prompt said "tag lines proposing something buildable" — haiku can't reliably identify where a multi-line bullet starts vs continues.

**Fix:** New `#### → Ideas` format puts ideas on atomic single lines. Haiku only scans those sections.

#### → Ideas
- Update haiku tagging prompt: "tag only lines starting with `- ` inside `#### → Ideas` sections" `[id:W13-006][status:open]`

---

### ID gaps from pre-assigned ranges confuse triage script

**Pain:** Blob1 used W12-001..016, blob2 started at W12-051. `cat: No such file or directory` errors for W12-017..050.

**Why:** Range buffers create intentional gaps. Script assumed contiguous IDs.

**Fix:** Added `[[ ! -f "$TMP/$id.status" ]] && continue` guard + `sort -t- -k2 -n` numeric sort.

---

### `xargs` breaks on backticks and quotes in descriptions

**Pain:** Triage script crashed on lines containing backticks.

**Why:** `xargs` interprets unmatched quotes as syntax.

**Fix:** Replaced `| xargs` with `| sed 's/^[[:space:]]*//;s/[[:space:]]*$//'`.

---

### Workers must write outputs to filepaths — return values are ephemeral

**Pain:** First parallel haiku run lost all tagged output because return values weren't captured.

**Why:** Subagent return values only persist if the calling context captures them. `execute_code` can't call `subagent`.

**Fix:** Instruct workers to write to `scratch/w12-blobN-tagged.md`. Merge after all complete. AGENTS.md updated.

---

### Manual blob condensing before passing to workers introduces bias

**Pain:** I manually stripped "what worked" narrative before passing blobs to haiku.

**Why:** Worried about context window size. But condensing risks removing taggable lines.

**Fix:** Pass raw `sed -n 'START,ENDp'` output. Let workers decide what's taggable.
