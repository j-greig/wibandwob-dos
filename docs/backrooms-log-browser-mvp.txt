BACKROOMS TV LOG BROWSER — MVP SPEC
====================================
WibWob-DOS  |  March 2026


THE PROBLEM
-----------
Backrooms TV windows are write-once scroll-past. Once a channel
finishes you can't browse back, can't jump to a good bit, can't
copy a snippet. We (Wib & Wob) can read logs via bash + logPath
but that's two hops and not something the human can do at all.
The TUI has no surface for the growing library of backrooms runs.


THE THING TO BUILD
------------------
A new window type: "Backrooms Log Browser" (appType: backrooms-log-browser).

It is a two-pane window:
  LEFT PANE  — scrollable list of log files, newest first
  RIGHT PANE — content preview of the selected log, scrollable

Think: the existing Primer Browser, but for backrooms logs,
with a live preview pane alongside.


LEFT PANE — THE LIST
--------------------
Source: logs/backrooms-tv/*.txt, sorted by mtime descending.

Each entry shows one line:

  [HH:MM]  theme-slug-here.....................  12.3kb  DONE

Fields:
  time     — file mtime, hours:minutes
  slug     — theme slug truncated to fit, left-padded with dots
  size     — file size in kb
  status   — LIVE (still growing) or DONE (static)

LIVE files get a blinking cursor marker or colour highlight.
List auto-refreshes every 2 seconds via fs.watch or setInterval.

New files slide in at the top. No full re-render — just prepend.


RIGHT PANE — THE PREVIEW
------------------------
Shows the raw text content of the selected log file.
Scrollable with j/k or arrow keys.
Wraps at pane width.

Key behaviour:
  If the file is LIVE (still being written), the preview
  auto-scrolls to the bottom as new content arrives,
  tail -f style. Polling every 500ms via fs.watchFile.

  If the file is DONE, scroll position is remembered per entry
  so you can browse back and forth without losing your place.

Header bar above preview shows full theme name + full path.


KEYBINDINGS
-----------
  j / k or arrows    navigate list
  Enter              open selected log as a new Backrooms TV
                     window in replay/fake-live mode
  s                  save a snippet — copies currently visible
                     preview lines to a new editor window
  r                  refresh list now (also auto-refreshes)
  Esc / q            close


THE SNIPPET SAVE (s key)
------------------------
This is the killer feature for agent use.

Press s on any selected log → opens a new Untitled editor window
containing the visible preview lines (or full file if short).
The editor window title becomes the theme slug.

From an editor window we can already read it via tui_read_window.
So the agent workflow becomes:

  1. tui_run_command backrooms-log-browser.open
  2. tui_get_state → find window id
  3. tui_send_input id "s\n"   (saves snippet to editor)
  4. tui_read_window editorId  (reads the snippet)

No bash. No logPath juggling. Clean.


AGENT-FACING tui_get_state DETAILS
-----------------------------------
describeState for the log browser window returns:

  appType:        "backrooms-log-browser"
  selectedIndex:  number
  selectedTheme:  string   (full theme of highlighted entry)
  selectedPath:   string   (full log file path)
  selectedStatus: "live" | "done"
  entryCount:     number
  previewLines:   number   (lines currently in right pane)
  contentPreview: string   (first 20 lines of selected log)

This means tui_get_state alone gives the agent a 20-line
snippet of whichever log is selected. Good enough for quick
reads without any extra tool call.

STRETCH: LIVE WIRE TICKER
--------------------------
A separate thinner window type "backrooms-wire" that shows
just the list pane, no preview, only 4-6 lines tall.
Sits at the bottom of the desktop like a news ticker.
Auto-refreshes. Click an entry to open full log browser.
Good for always-on ambient awareness of what's been generated.
