# E022 — WibWobWorld Restore & Layout Fidelity

## TL;DR

WibWobWorld and its ISO companion window silently restore into wrong state on every
restart. Four root causes identified in #116 (Codex review). This epic closes all four
plus two layout fill bugs found during the 2026-03-07 ISO/hybrid session.

All bugs are related: they are all symptoms of WibWobWorld's render state and geometry
not surviving a restart cycle.

## Root Causes (from #116 and session archaeology)

**RC-1 — ISO restore: ephemeral file path, not terrain params**
`wibwobworld-iso` serialises `sourcePath` — an absolute path into `scratch/captures/`
which is gitignored and ephemeral. On restart the file may be gone → load-error branch.
If it ran before terrain was loaded, `sourcePath` is `undefined` → silently reopens
the wrong (latest) capture file.
_Files:_ `modules-private/wibwobworld-iso/index.ts ~251, ~356-365`

**RC-2 — No ordering contract between paired windows**
WibWobWorld and ISO restore independently in array order. ISO can restore before the
main world has generated terrain. The main window then rerenders and the ISO world no
longer matches.
_Files:_ `src/core/app-controller.ts ~332-336`

**RC-3 — restoreSafeMode unconditionally drops renderMode**
Main window serialize faithfully saves `renderMode: "hybrid"` but restore overrides
it to `"contours"` via the `__restoring` flag bandage (commit `ae0ad94`). The user's
last render mode is silently lost on every restart. High daily pain — every session
requires manually re-switching mode.
_Files:_ `modules-private/wibwobworld/index.ts ~186-190`

**RC-4 — Microapp geometry not reapplied on restore**
`module-loader.ts registerSnapshot` returns `undefined`, so `restoreWindowSnapshot()`
cannot reapply saved `left/top/width/height` for any microapp window. Both WibWobWorld
and ISO open at default size/position regardless of what was saved.
_Files:_ `src/services/module-loader.ts ~259-261`

**RC-5 — ISO right pane in hybrid mode renders smaller than standalone ISO**
In hybrid mode the right pane uses a world generated by `worldDimensions(mapViewport)`
(large, contour-optimised) fed into `renderIso` — the stride/scale compresses it down
to a small diamond. Standalone ISO mode sizes the world directly from canvas dimensions
(N×N iso-optimised). The right pane should match standalone ISO quality.
_Files:_ `modules-private/wibwobworld/index.ts render() hybrid branch`

**RC-6 — Debug breadcrumbs left in production code**
`render:dims`, `render:layout-start`, `render:hybrid-panes`, `render:artifact-built`,
`render:iso-start/done`, `render:iso-setcontent-done`, `render:before-screen-render`
were added for diagnosis (session 2026-03-06) and never stripped. Noise for future
agents; controlled by `WIBWOBWORLD_DEBUG=1` so low-risk but untidy.
_Files:_ `modules-private/wibwobworld/index.ts`

## Stories

### S01 — Strip debug breadcrumbs (RC-6)
Status: [x] done

Remove the granular `render:*` breadcrumb calls added during diagnosis. Keep the
env-gated `debugWibWobWorld` function and any `setup`, `render:focus`, `render:end`,
`render:error` calls that carry ongoing diagnostic value.

AC:
- [ ] No `render:dims`, `render:layout-start`, `render:layout-done`, `render:hybrid-panes`,
      `render:artifact-built`, `render:iso-start`, `render:iso-done`,
      `render:iso-setcontent-done`, `render:before-screen-render` calls remain
- [ ] `debugWibWobWorld("render:end", ...)` and `debugWibWobWorld("render:error", ...)` kept
- [ ] `bun run typecheck` clean
- [ ] App opens WibWobWorld in all 5 modes without freeze

---

### S02 — Preserve renderMode on restore (RC-3)
Status: [x] done

Remove the `restoreSafeMode` bandage that forces `"contours"` on every restore.
Let the serialised `renderMode` be honoured directly.

5 Whys:
1. Every restart drops the user's last mode → must re-switch manually.
2. `restoreSafeMode` unconditionally overrides `renderMode` to `"contours"`.
3. It was added as a bandage because hybrid/iso caused a blessed freeze on restore.
4. The freeze was caused by `infoBlock.update()` on a `width=0` scrollable node.
5. That is now guarded. The bandage is no longer needed. Remove it.

AC:
- [ ] `renderMode` field in `describeState()` round-trips through workspace save/restore
- [ ] Restart with WibWobWorld in hybrid → reopens in hybrid
- [ ] Restart with WibWobWorld in iso → reopens in iso
- [ ] Restart with WibWobWorld in terrain/contours/firstperson → reopens in same mode
- [ ] No freeze in any restored mode (verify with API health check post-open)
- [ ] `bun run typecheck` clean

---

### S03 — ISO serialises terrain params not file path (RC-1)
Status: [ ] not-started

`wibwobworld-iso` should serialise `{ seed, terrainIdx, seaLevel, levels }` and
regenerate terrain on restore. The ephemeral `sourcePath` must not be the restore key.

AC:
- [ ] `describeState()` in `wibwobworld-iso` includes `seed`, `terrainIdx`, `seaLevel`, `levels`
- [ ] Restore reads those params and regenerates terrain (no file read)
- [ ] If params are missing from snapshot (legacy restore), opens cleanly with a default world
- [ ] `sourcePath` may still be written to disk for export workflows — just not used for restore
- [ ] `bun run typecheck` clean
- [ ] Restart with ISO window open → reopens same terrain (visual match)

---

### S04 — Microapp geometry restored on restart (RC-4)
Status: [x] done

`module-loader.ts registerSnapshot` must return the snapshot geometry so
`restoreWindowSnapshot()` can reapply `left/top/width/height`.

AC:
- [ ] `registerSnapshot` returns geometry from the serialised snapshot
- [ ] WibWobWorld reopens at saved position and size after restart
- [ ] ISO window reopens at saved position and size after restart
- [ ] Other microapps (world-chatroom etc.) unaffected
- [ ] `bun run typecheck` clean

---

### S05 — Hybrid iso right pane fill parity (RC-5)
Status: [ ] not-started

In hybrid mode the right iso pane should render a world sized to the iso pane canvas
dimensions (same as standalone ISO mode), not the full contour world strided down.
The two worlds (left contour, right iso) must be generated independently — same seed,
different size targets.

AC:
- [ ] Hybrid right iso pane fills its half at the same density as standalone ISO mode
- [ ] Hybrid left contour pane unaffected — still uses worldDimensions(mapViewport)
- [ ] Both panes derive from same seed/seaLevel/terrainIdx (visual consistency)
- [ ] No performance regression (artifact cache still applies to both worlds)
- [ ] `bun run typecheck` clean

---

### S06 — Ordering contract for paired WibWobWorld + ISO restore (RC-2)
Status: [ ] not-started

ISO window restore must wait for WibWobWorld to finish terrain generation before
loading. Implement a simple parent/child dependency: ISO checks if WibWobWorld is
present in the restore batch and defers if so.

This is the architectural story — lower priority than S02-S04 which fix the daily pain.

AC:
- [ ] ISO restore does not begin until WibWobWorld emits `terrain:ready` or equivalent
- [ ] If WibWobWorld is not in the restore batch, ISO restores independently (no deadlock)
- [ ] `bun run typecheck` clean

## Do Not Do

- Do NOT extend the `restoreSafeMode` bandage for any reason
- Do NOT use `sourcePath` as the restore key for ISO
- Do NOT use `kill -9` during testing — use `bash scripts/restart.sh`
