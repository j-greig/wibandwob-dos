(1) Built-in editor undo is basic -- single character undo, not grouped
(2) Built-in editor has NO syntax highlighting in edit mode
(3) Document Reader has syntax-highlighted code blocks via markdown-service
(4) Markdown view mode in text-windows.ts and document reader both use
    renderMarkdownFile() from markdown-service.ts -- SAME engine
(5) Slap editor has no scrollbar widget, scrolls via cursor movement
(6) Slap editor only opens via command args, no interactive file picker

CONSOLIDATION OPPORTUNITIES
============================

1. MERGE BUILT-IN EDITOR + SLAP EDITOR
   The Slap Editor has strictly better editing features: gutter, line
   numbers, selection, clipboard, find, grouped undo. The built-in editor
   has: file picker integration, save-as, markdown view toggle.
   PROPOSAL: Port Slap Editor features into built-in editor, or replace
   built-in editor engine with EditorEngine. Keep the text-windows.ts
   frame/chrome and markdown view mode toggle.

2. DOCUMENT READER = BUILT-IN EDITOR (VIEW MODE)
   Both use renderMarkdownFile() from markdown-service.ts. The document
   reader is essentially a read-only version of the editor's view mode.
   PROPOSAL: Could eliminate Document Reader as a separate window type.
   Opening a .md file in the editor already defaults to view mode.
   The reader adds: separate window kind, dedicated scroll keys, context
   menu figlet toggle. These could live in the editor view mode.

3. SYNTAX HIGHLIGHTING GAP
   markdown-service.ts has syntax highlighting for code blocks (in view
   mode / reader). Neither editor has syntax highlighting in EDIT mode.
   PROPOSAL: Extract the syntax highlighter from markdown-service and
   make it available to the edit-mode renderer. This benefits both
   editor engines.

4. ZINE SIDEBAR vs FILE MENU
   The Zine uses createSidebarPanel for file navigation. This could be
   replaced by opening files from the File menu or command palette,
   giving the Zine full-screen editing space.
   TRADEOFF: Sidebar gives quick switching between zine panels. File
   menu is slower but cleaner. Consider: keep sidebar as optional
   (toggled off by default), rely on File menu / keyboard for open.

5. FILE PICKER CONSISTENCY
   Three file-open UIs exist:
   a) OverlayManager.openFileBrowserPrompt() -- modal overlay
   b) createSidebarPanel() -- sidebar list
   c) openFileManagerWindow() -- full file manager
   PROPOSAL: Standardise on (a) as the primary open-file path for all
   apps. (c) stays as a power-user tool. (b) is module-specific.
