       keyboard path bypasses it.

       src/core/menu-overlay-manager.ts  openMenu()  line 88

       openMenuLabel before deciding whether to open or close. Wire the

CHORE 4: Responsive figlet in Hello World (and SDK-ise the pattern)
--------------------------------------------------------------------
WHAT:  Hello World renders "HELLO WORLD" in larry3d at module load
       time, bakes the banner into a fixed-size window. If the window
       is resized narrower, the text clips. It should adapt:

       Wide window   -> larry3d (current, ~10 lines tall, ~80+ cols)
       Medium window -> equivalent of H2 font "small" (~5 lines tall)
       Narrow window -> equivalent of H5/H6 plain CAPS + underline

WHERE: microapps/hello-world/index.ts

HOW IT WORKS IN MARKDOWN TODAY (for reference):
  markdown-service.ts renderFigletHeading() takes a width param.
  It calls tryFiglet(text, font, width) which runs:
    figlet -f <font> -w <width> <text>
  If the output exceeds width, tryFiglet returns null.
  It then tries fallbackFonts in order (e.g. slant -> small -> term).
  If ALL fonts fail, it falls back to plain CAPS text.

  BUT: the fallback chain is per heading LEVEL, not across levels.
  An H1 tries its own fonts (slant, small, term) but never downgrades
  to use H3's threepoint or H5's plain CAPS. So the "responsive"
  behaviour is really "try smaller fonts within the same tier."

PROPOSED APPROACH for Hello World (and future SDK primitive):

  1. Define a responsive font cascade:
     [
       { font: "larry3d",    minWidth: 80 },
       { font: "slant",      minWidth: 60 },
       { font: "small",      minWidth: 40 },
       { font: "digital",    minWidth: 25 },
       { style: "caps",      minWidth: 0  },   // plain fallback
     ]

  2. On window resize, pick the first entry where minWidth <= available
     width. Re-render the figlet. If tryFiglet still fails (text too
     long even at that width), fall through to next.

  3. SDK PRIMITIVE: extract this as a reusable function:
       responsiveFiglet(text, width, cascade?) -> string
     or better, as a createResponsiveFigletDisplay() UI primitive
     that auto-re-renders on resize.

  4. Integrate with existing createFigletDisplay() from ui-parts.ts,
     which already takes a renderText callback. The callback just
     needs to receive the current width and pick the right font.

  See: scratch/audit-figlet-markdown-rendering.txt for full landscape.
