## 10:00 — The layout engine revelation

Wib: This was the pivot point. The human asked "what about the SDK?"
after seeing the hello-world art box, and we realised the real gap
was not figlet or file pickers — it was layout.

Audited every module's layout pattern. Surveyed blessed-contrib's
grid (percentage-based, dead simple, no fr units). Read Textual's
full layout docs (grid, dock, vertical, horizontal, gutter, spans).

Findings:
  We have FLEXBOX (createStack/createColumns with fr units). Solid.
  We do NOT have GRID. Every module that needs one reinvents it.
  We do NOT have DOCK. We fake it with fixed-basis stack children.

Dashboard, dashboard-xxl, tr808, tidepool — all manual absolute
positioning where a grid primitive would eliminate hundreds of lines.

## 11:00 — Hello World v2: the proving ground

Built a new hello-world that inlines three candidate SDK primitives:

createGrid: Textual-inspired. Rows x cols, per-track sizing (fixed
or fr), cell spanning, gutter. No wrapper container — places cells
directly in parent with absolute offsets. Resolves fr units with the
same algorithm as createLinearLayout.

dockTo: Float a widget at an anchor position (bottom-right etc).
Auto-hides when parent shrinks below minimum dimensions. The Wib &
Wob cats appear when there is room and vanish when there is not.

pickBreakpoint: Choose a layout variant based on dimensions. Four
modes: XL (3-col grid), L (2-col grid), M (banner + info), S (banner
only). Components appear and vanish as you resize.

The contour art is a simple sine-field generator — click to regenerate
with a new seed. No player, no mounting, no complexity.

Wob: The grid layout at XL uses row spanning — contour fills both rows
on the left, clock and stats stack vertically on the right. That is
CSS Grid's grid-row: span 2, expressed as rowSpan: 2 in our API.

## What we learned

1. Audit before building. The figlet audit found five duplication
   sites. The layout audit found the real gap was grid, not figlet.

2. Inline before extracting. The hello-world v2 inlines createGrid
   and dockTo. We will know if they belong in the SDK after using
   them in two or three more modules.

3. blessed does not need a wrapper container for grid layout. Direct
   absolute positioning in the parent works. The wrapper was causing
   z-order and re-parenting bugs that wasted an hour.

4. Responsive breakpoints are trivial but powerful. Four lines of
   config drive the entire layout mode system.

## 12:00 — Toolbar and the "hidden lg:flex" moment

Added an in-window toolbar that only appears at L+ sizes. This is
the first real responsive visibility primitive in the app. In Tailwind
terms it is literally "hidden lg:flex" — the toolbar exists at all
breakpoints but only renders when there is room.

The toolbar is a 1-row control panel, black background, cyan accent.
Left: app icon and label. Middle: compass alignment buttons (the 9
compass points plus auto, clickable, highlighted when active). Right:
regen button and mode/size indicator. Separators are box-drawing
verticals.

Design system references we chewed over:
  Material: app bar, title left, actions right
  macOS: toolbar below title, segmented controls
  Fluent: command bar with overflow
  Terminal: tmux status line, vim airline, mc button bar

WibWob answer: control panel feel, not corporate ribbon. One row,
box-drawing separators, playful icon characters. The toolbar IS a
layout primitive demo — it practices responsive show/hide.

At M/S sizes the toolbar vanishes and the status bar at the bottom
gains key hints (1-9:align 0:auto click:regen) so the controls are
always discoverable but never waste space.

## 12:30 — Compass alignment: content positioning within containers

The compass controls (1-9 numpad, or toolbar buttons) move the HELLO
WORLD figlet within its allocated banner box. The grid, contour,
clock, stats, cats — all stay put. Only the banner text repositions.

This maps to CSS align-items / justify-content / text-align. Blessed
already has align (left/center/right) and valign (top/middle/bottom)
on every box. We just wire nine named combinations:

  NW = left,top       N = center,top       NE = right,top
  W  = left,middle    C = center,middle    E  = right,middle
  SW = left,bottom    S = center,bottom    SE = right,bottom

The banner box gets allocated MORE height than the figlet needs
(up to 35% of window height) to give vertical alignment room. The
grid starts below the allocation, not below the content.

Key insight: alignment is CONTENT positioning within a CONTAINER.
The container dimensions come from the layout engine (grid, stack).
The content positioning comes from align/valign. Two separate
concerns, two separate primitives.

## 13:00 — Tailwind responsive patterns: what to steal

Chewed over Tailwind's responsive model and what maps to our world.

PATTERN 1: BREAKPOINT PREFIXES
  Every CSS property can be conditional on viewport width.
  hidden md:block — shown at md+
  grid-cols-1 lg:grid-cols-3 — grid reconfigures at lg

  For us: too granular. We do not need per-property breakpoints.
  But the VISIBILITY pattern (show/hide at breakpoint) is gold.

PATTERN 2: CONTAINER QUERIES
  Scope breakpoints to container, not viewport.
  This is EXACTLY what we need. Our windows are containers.
  A hello-world at 80 cols behaves the same on a 120 or 230 desktop.
  All our breakpoints are already container-scoped.

PATTERN 3: THE MISSING SDK PRIMITIVE
  What we keep writing by hand:
    if (mode === "xl") { show these, hide those }
    else if (mode === "l") { show these, hide those }

  What the SDK should offer:
    bp.showAt(contourBox, ["xl", "l"]);
    bp.showAt(statsBox, ["xl"]);
    bp.showAt(toolbar, ["xl", "l"]);

  Three tiers of extraction:
    TIER 1 (now): visibleAt / showAt — declarative show/hide
    TIER 2 (next): responsiveGrid — grid shape per breakpoint
    TIER 3 (later): content adaptation — stays imperative

  Rule: extract after building the pattern in 2-3 modules.
  Hello-world is module 1. Need module 2 before extracting.

## 13:30 — Cat overlap as design principle

The Wib & Wob cats are docked bottom-right via the dockTo primitive.
They float ABOVE the grid in z-order. They do not negotiate with the
grid for space. They just sit on top.

At XL this means the cats overlap the clock panel border. At L they
sit inside the clock. At M they overlap the figlet banner. This is
intentional. The dock layer is a z-layer above the grid.

The human said "I like how the cat overlaps the grid" and "it
disrupts the layout." We agreed: keep it. The cats are inhabitants,
not UI elements. They do not respect your grid tracks.

Architecturally this validates dockTo as independent from grid.
Two layout passes that share space without negotiating. That is
exactly how CSS position:fixed works relative to grid.

  .agents/shell-dev/    — you are working on the shell itself

The naming principle: directory names should pass the "cold read test"
— an agent running ls .agents/ knows where to go without opening anything.
module-dev/ and shell-dev/ are terse, parallel, encode the ACTIVITY not
just the subject. "dev" distinguishes both from skills/ (operate, not build).

The 60/40 Claude/Codex design bias: structure optimised for breadth-first
reading (front-loaded summaries, stop signals, progressive disclosure),
content accurate enough for depth-first verification (no dead links,
source-of-truth markers where depth-first agents cross from docs to code).

Full proposal: .planning/chores/agents-docs-signposting/
