# Phase 0 — The First Refactor Pass

Goal:

**Make the codebase understandable without changing behaviour.**

No feature changes.
No SDK design yet.
Just architecture discovery.

---

# Step 1 — Generate architecture maps

Run these tools immediately.

### Dependency graph

```bash
npx depcruise src --include-only "^src" --output-type dot | dot -T svg > architecture.svg
```

This gives you:

* module dependency graph
* architectural shape
* coupling hotspots

---

### Circular dependencies

```bash
npx madge src --circular
```

These are **refactor targets**.

Circular imports usually indicate:

* Godfiles
* bad layering
* shared state

---

### Dead code

```bash
npx knip
```

You will likely find:

* unused utilities
* unused exports
* abandoned experiments

Remove nothing yet — just list them.

---

# Step 2 — Identify Godfiles

List files over ~600–800 lines.

These usually contain mixed responsibilities.

Typical patterns:

* UI + state + commands in one file
* CLI logic mixed with UI
* Blessed widgets + app logic intertwined

Create a list:

```
Godfile candidates:
- src/foo.ts (1300 lines)
- src/runtime.ts (900 lines)
- src/dashboard.ts (1000 lines)
```

These become **refactor targets later**.

---

# Step 3 — Classify the codebase

Create a temporary map.

Example:

```
src/
  ui/
  runtime/
  commands/
  services/
  microapps/
  sdk/
```

You don’t need to move files yet.

Just **label them conceptually**.

---

# Step 4 — Identify the “core verbs”

Look for functions that represent **actions in the system**.

Examples might be:

```
openWindow()
renderDashboard()
dispatchCommand()
loadModule()
spawnApp()
```

These are your future **application services**.

Right now they’re probably scattered across files.

Write them down.

---

# Step 5 — Identify the real host responsibilities

From the codebase you will probably discover the host actually does things like:

* window manager
* focus manager
* command dispatcher
* microapp loader
* layout engine
* render loop

This becomes the **runtime boundary**.

---

# Step 6 — Confirm the three interface surfaces

You mentioned earlier:

* TUI
* CLI
* API

You want **parity across them**.

Meaning:

```
command → CLI
command → API
command → TUI
```

The same underlying **service function** should power all three.

Example future architecture:

```
service: openWindow()

TUI → openWindow()
CLI → openWindow()
API → openWindow()
```

Right now they probably diverge.

Just confirm that.

---

# Step 7 — Stabilize the test harness

Before refactoring anything, create **one reliable runtime test**.

Example:

```
start host
open dashboard
press key
capture screen
assert output
```

Use:

* node-pty
* bun test / vitest

This protects you during refactor.

---

# Step 8 — Define the first extraction target

The **first refactor** should be tiny.

Good candidates:

* command system
* event bus
* window model
* layout rules

Not everything at once.

---

# What you should **not do yet**

Do not yet:

* redesign SDK
* rename modules
* move lots of files
* create microapp folders
* rewrite UI

All of that comes **after architecture clarity**.

---

# The mental model to hold

Right now your task is:

**archaeology, not architecture**

You are excavating the system.

Once you see it clearly, the architecture will almost suggest itself.
